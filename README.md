# zcrypto

A practical guide to `std.crypto` in Zig 0.16 — what's in there, what each
primitive is for, how they compose safely, and minimal working examples.

The only prior deep guide is Frank Denis's "A tour of std.crypto in Zig 0.7.0"
(November 2020). It's authoritative but 6 years old and assumes crypto expertise.
This fills the gap: current (0.16), readable, explains the *why* not just the *what*.

## Layout

```
docs/map.md         — start here: mental model, families, decision guide, danger zones
docs/surface.md     — the developer-facing surface: 134 primitives by family (generated)
docs/structure.md   — the full structural map: 400 containers with exact counts (generated)
docs/clusters.md    — containers grouped by structural shape, with an SVG (generated)
docs/inventory.md   — annotated reference: each primitive with a plain-English note
src/                — Zig reflection tools that extract the data (dump / maptree / surface)
scripts/            — Nushell glue: run the tools, clean, group, render (see data/README.md)
data/               — generated datasets (CSV/TSV/JSON), regenerable and the source of truth
examples/           — minimal working Zig per primitive (Phase 4, not started)
```

Toolchain is **Zig** (reflection-based extraction) + **Nushell** (glue and querying)
only — no Python, no duckdb. Every dataset under `data/` is regenerable from the
scripts and idempotent.

## Primitives

std.crypto (Zig 0.16) exposes **134 developer-facing primitives** across 10 families
(hashing, AEAD, MACs, stream ciphers, signatures, KEM, key exchange, KDF, NaCl boxes,
one-time auth) plus password hashing via functions. The full public tree is **400
containers** once builders, config types, and curve internals are included.

→ **[docs/surface.md](docs/surface.md)** — the authoritative list: every dev-facing
primitive grouped by family, generated by reflection (`src/surface.zig`).

→ **[docs/map.md](docs/map.md)** — the mental model: how the families relate,
which primitives compose correctly, and a quick-decision guide.

---

## The composition rule

The most important thing std.crypto doesn't document: **which primitives belong
together.** A stream cipher alone encrypts but doesn't authenticate. Using the wrong
combination is worse than not encrypting. See `docs/map.md` and (coming) `docs/composition.md`.
