zephem — how the data flows

One source, read two ways → two spines + overlays → one join. Every arrow points one way: a star, not a loop.

spine — a primary dataset (one per reader) the join — reconciles both spines, reads no source the three provenance buckets

Two readers, two spines. scan.zig reads text → nodes.tsv (the map). resolve.zig runs the compiler → resolved.tsv (resolved values). Everything else hangs off these two. Overlays (decls / tunnels / index) add a different fact on the same spine, keyed by path. canon.tsv is a view — it labels every name by which reader can see it. The repetition you feel is in the number of checks, not the data: the source is parsed three times for three different facts, and several verifiers reconcile the same two spines.
